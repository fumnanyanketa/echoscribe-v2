# Drift patrol, 2026-09-04, plan rows 3 and 4

Scope: the two surfaces records 0005 and 0006 are about to build, Settings,
Vocabulary and Settings, Languages, plus the one thing record 0006 changes on a
screen that already exists, the pill's transcript line. **Nothing was built
yet.** This is the pass the registry's own header demands before a build, "a
component not on this list does not exist", and it ran in the same session as
the two records rather than after them, because the user was away and asked for
both features end to end.

This is the second patrol written to a file. The first is
[2026-09-04.md](2026-09-04.md), earlier the same day, for the Settings,
Dictation surface.

**Two things about this patrol are unusual and worth saying.** It is a patrol
before a build rather than after one, so every finding is a gap in the system
rather than a discipline slip: there is no code yet to be undisciplined. And two
of the findings are corrections to rows this list already held, which is the
more interesting half, because a wrong row is worse than a missing one. A
missing row stops a build; a wrong row gets followed.

## What was clean

- **No new token is needed, anywhere.** Every one of the new or corrected rows
  is built from tokens that exist: `--color-surface-subtle` for the two fields,
  and see the finding above for why it is not `sunken`;
  `--color-border-control` for their edges, which is mandate rule 7;
  `--color-surface-subtle` at `--radius-md` for a term row, which is the fill
  this section already uses for a row; `--color-danger-on-light` for Remove,
  which `Secret field` already established on a light surface;
  `--color-ink-caption` at `--text-xs` for both captions.
- **No new contrast pair, after one was corrected into an existing one.**
  `python design/check-contrast.py` was run twice, before and after the `sunken`
  finding above, and all 59 pairs pass, unchanged. Every pair the new rows use is
  now already audited under another name, and each row says which: the term and
  its label as "Keycap text on a row", the `CHOSEN` badge as "Hotkey CHOSEN
  badge", the two captions as "Caption on a row", Remove's label as "Danger text
  on light", the two field edges as "Control edge on a row". Nothing was added
  to that file, which is the right outcome rather than a skipped step: the one
  pair that would have needed adding was a failing one, and the fix was to reach
  for the audited fill instead of auditing a new one. **What that file still does
  not cover is `--color-surface-sunken` behind anything at all**, and the History
  `Search field` is the row that will need it.
- **Reuse beat reinvention four times**, which is the rule that is least visible
  in a diff. `Language filter` is History's `Search field`, not a new field.
  `Language list`'s chosen marker is `Hotkey choice`'s badge, not a new marker.
  `Settings, could not be read` was widened rather than copied. The
  `Setting error line` is one shape now serving four surfaces.
- **Nothing on the "not in the registry, on purpose" list crept in.** No
  dropdown for 64 languages, which was the obvious wrong answer and is the
  reason `Language filter` exists instead. No modal for a Remove. No toast for a
  successful add. No tooltip on the Multilingual row, which is why it has a
  second line instead.
- **The two-signal rule is carried by words in every new state.** The chosen
  language is a fill and the word `CHOSEN`. A full list is a changed caption and
  an unavailable Add. An empty field is an unavailable Add and an empty field.
  No new state rests on colour.
- **The CJK font fallback was already law and did not need registering.**
  `design/design-system.md` says the sans stack falls through to the system
  Japanese, Korean and Chinese faces and calls that fallback "real and
  load-bearing", naming the language list by name. Record 0006 leans on a
  sentence that was written before it.

## Registry

**Seven added, five corrected in place, one duplication avoided, and one
failing contrast pair caught before it was built.**

Added, all under Settings: `Multilingual row`, `Language filter`,
`Term add field`, `Term row`, `Term room left`, `Vocabulary empty state`, and
`Vocabulary, could not be read`. That last one is registered as explicitly
**not** a component of its own, so a build finds the state named rather than
deciding an empty list and an unreadable one look the same, which is the one
mistake it exists to prevent.

Corrected in place: `Language list`, `Default marker`,
`Settings, could not be read`, `Setting error line`, and the pill's
`Transcript line`.

The duplication avoided is the one that would have been easiest to commit: a
"Languages, could not be read" and a "Vocabulary, could not be read" row each
restating `Settings, could not be read`. Four rows saying the same thing is how
four of them start to differ.

## System changes

**None proposed, and that is deliberate.** Nothing here needed the user's
approval on the law itself: no token was invented, no pair went unaudited, and
the one place a rule was not followed to the letter, the vocabulary empty state,
is registered as a deviation with its reason in the row rather than by quietly
editing the rule. `design/design-system.md` is untouched.

One thing about the law is worth flagging for the user rather than changed. Its
empty state rule reads as though every empty state in the app should show the
hotkey and offer an action. That was written for History, and it now has one
registered exception. If a third surface needs the same exception, the rule
itself is what is wrong and that is a conversation, not a patrol.

## Routed to /develop

Nothing to fix, because nothing is built. What is handed over is the eight rows
above as the spec for the two surfaces, plus three things a build must not do,
each of which this patrol expects to be tempting:

1. **Do not give a term row a chosen, active or enabled state.** Every word in
   the list is in force at all times, and a word shown as not-in-force is the
   one thing record 0005 refuses.
2. **Do not reach for a dropdown, a modal or a toast**, for the 64 languages, a
   Remove, or a successful add. All three are on the not-in-the-registry list.
3. **Do not hold a list of right to left languages.** `dir="auto"` is the whole
   mechanism, and a build that adds a language list to go with it has made the
   pill wrong for a bilingual person.
4. **Do not reach for `--color-surface-sunken` for either field**, however well
   its comment fits. Its control edge is 2.87:1 and the mandate needs 3:1. Both
   rows say `--color-surface-subtle` and both say why.
