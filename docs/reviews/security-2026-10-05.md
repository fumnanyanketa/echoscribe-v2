## Promised but not built

None. Every refusal the six `## Risk` sections promise was found in the
code:

- **Record 0002.** Typing into a password field is refused (`typing.rs`,
  AC-20). The keyboard hook reads only the virtual key and press state and
  discards everything but the chosen modifier (`hook.rs:122-160`). No code
  path writes audio or any file (`File::create`, `write_all` and
  `fs::write` do not appear outside tests). The Deepgram key lives in
  Windows Credential Manager and only its last four characters ever come
  back (`deepgram_key.rs`). Nothing in the interface holds the key or the
  audio.
- **Record 0003.** The authorization code, the access token and the
  refresh token never reach the interface: `AccountView` carries a display
  name, an email, initials and a date, nothing else (`auth_state.rs:39-49`),
  and no interface file mentions a token. State and PKCE mismatches are
  refused (`handoff.rs`, `StateMismatch`). A refused refresh ends the
  session instead of continuing online (`renewal.rs:99`). No Clerk secret
  key exists; the app ships a public OAuth client id, which is meant to be
  public. The one thing record 0003 did not foresee is the browser-side
  session, which is the Medium finding above and is new, not a broken
  promise.
- **Record 0004.** All three windows carry only `core:event:allow-listen`
  and `core:event:allow-unlisten`; `core:default` is gone from `main`
  (`capabilities/*.json`). The dashboard is refused to anyone not signed in
  by the Rust commands themselves.
- **Records 0005, 0006.** Terms and language codes never reach the
  Deepgram address unencoded or unchecked; both refusals are held by
  tests that name the exact strings.
- **Record 0007.** No `innerHTML`, `outerHTML`, `insertAdjacentHTML`,
  `document.write`, `eval` or `new Function` anywhere under `src/`, and the
  history screen's source guard still fails the build if one appears.
  Today's new interface code (the sign-in screen's tiles and wordmark, the
  key setup steps, the rail's account menu) sets every value with
  `textContent`.

## What the production set-up added, and how it was checked

- **Clerk production** holds the user accounts. The app talks to it only
  over HTTPS to a fixed domain. The OAuth client's secret, which Clerk
  generated, was never copied anywhere: the app is a public PKCE client and
  has no use for it.
- **Google sign-in** is backed by an OAuth client in the user's own Google
  Cloud project. Its client secret was pasted by the user straight into
  Clerk's dashboard and exists nowhere in this repository, this session's
  files, or any log. Google only receives the basic profile scopes (`openid`,
  `email`, `profile`). The app itself never talks to Google; Clerk does.
- **DNS** at Dynadot: five Clerk records and one GitHub Pages record, all
  on `*.echoscribe.exentrik.co`. The bare domain was not touched.
- **The public site** is two static pages and a stylesheet, no scripts, no
  forms, published by a workflow that uploads only `site/`; the plan,
  decision records and evidence stay out of it. The privacy policy's claims
  were checked against the code before publishing and match it.

## Clean

Checked and found fine: no secrets in the working tree or in 75 commits of
history; `.env` files ignored since before sign-in was built; no HTML sinks
in any interface file; every Rust `eprintln!` in the sign-in and dictation
paths prints a machine reason and never an email, a token or a key; the
interface's `console.*` lines print refusal reasons only; one SQLite file;
audio never written; the microphone never opens without the pill; the
hook discards every key but the chosen modifier; capabilities narrowed to
two event permissions per window; a real CSP; the dependency layer clean of
vulnerabilities.
