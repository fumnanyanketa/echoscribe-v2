# `/test`, 2026-09-04, plan rows 3 and 4

One report for both rows, because both were built in one session and the two
most valuable tests cover them together: the request to Deepgram carries a
language and a vocabulary at the same time, and neither may drop the other.

**80 tests for these two features**, all in Rust, run with `cargo test` from
`src-tauri/`. The whole suite is **302 passing, 0 failing**, up from 253 before
this session. 65 are in the two new feature folders; 11 assert what is actually
asked of Deepgram; 2 guard the dictate feature's own reads; 2 cover the new
history column and its migration.

## What a machine now watches, and what a person still has to

This is the honest half of the report. **Nine of the 26 criteria across the two
records cannot be automated in this project**, and every one of them is a
person's job at `/check verify` and after every change, forever.

## Not covered, and why. A person checks these

**Nothing here is faked.** Each one is a real promise with no machine watching
it, and saying so is more useful than a number.

1. **Everything either screen draws.** This project has no JavaScript test
   runner and `/audit` has not chosen one, so `src/vocabulary/vocabulary.js` and
   `src/language/language.js` have no automated coverage at all. That leaves the
   visible half of six criteria to a person: record 0005's AC-1, AC-11 and
   AC-12, and record 0006's AC-1, AC-9 and AC-10. What Rust does guard is the
   two things a screen could get wrong invisibly: that neither holds a sentence
   or a limit Rust owns, and that the language wording and the language codes
   have not drifted apart. **Choosing a JavaScript test runner is a decision
   nobody has made**, and it is worth making before a fourth screen lands.
2. **Whether keyterm actually fixes the words it is given.** Record 0005's
   whole value, and its own Still open says so. It needs a name Deepgram
   reliably mis-transcribes, said, added, and said again. No test can stand in
   for that: it is the feature's own `Done when:`.
3. **Whether a language transcribes correctly.** Record 0006's AC-3 stands for
   64 choices and a machine can only check that Deepgram was asked. The evidence
   file has to name which language it was proved in, and two are worth running
   for the script alone: one non-Latin, one right to left.
4. **Whether the pill's one locked 472x52 geometry fits a script it was not
   measured with.** `dir="auto"` settles direction and settles nothing about
   fit. Record 0006's Still open carries it.
5. **The filter, as a thing a person uses.** That 64 rows can be narrowed, that
   clearing shows them all again, and that the no-matches state reads correctly.
6. **That a change mid dictation really does wait for the next one.** Both
   guards prove the reads sit before the microphone opens and happen once, which
   is the only thing that makes the promise true, but proving it live means
   changing a setting while speaking.
7. **The whole request, as Deepgram receives it.** The tests assert the query
   string `Options::urlencoded` produces, which is the text the SDK will send.
   They do not prove the SDK then sends that text.
8. **A second account's dictations really not using the first's words.** The
   store tests prove the rows are invisible across accounts, which is the
   mechanism; the live half needs two accounts and two dictations.
9. **Whether Deepgram refuses `punctuate` for any language.** Undocumented, per
   record 0006's Still open. The test only proves this app never turns it off.

## Deliberate fakes, skipped

None to skip. Neither feature has a stand-in: the store is real SQLite, the
rules are the rules, and the request is the real one. The one thing that looks
like a fake and is not is `catalog::is_offered`, which is compiled out of the
app and exists only for the two drift guards; that is stated on the function.

## Breaking things on purpose

Green proves nothing on its own, so three invariants were broken deliberately,
each chosen to catch the failure mode `/test` warns about: a test that asserts
on a helper rather than on the path that uses it.

| What was broken | What should fail | What did fail |
|---|---|---|
| `stream_options` stops adding the keyterms, by putting `false &&` in front of the check | The request tests, not a guard | **5 tests**, all of them request tests: the plain vocabulary one, the ampersand one, the phrase one, the non-Latin one, and the one that pairs a vocabulary with a language. So they read the real query and not the SDK's behaviour |
| The language read moves from before `microphone::open` to after it | The ordering guard, with a message naming AC-4 | **1 test**, `the_language_and_the_words_are_read_before_the_microphone_opens`, printing "A language changed during a dictation could then reach it, which record 0006's AC-4 forbids" |
| `BUDGET` raised from 400 to 4000 | The safety property, not just the constant | **4 tests**, and the load-bearing one said it in the right words: "the worst list the rules allow costs 3100, which is not provably inside Deepgram's 500 token limit". So the bound is being computed from the rules rather than asserted as a number |

All three were undone and the suite is back to 302 passing, `cargo clippy
--all-targets -- -D warnings` clean, and `cargo fmt --check` clean.

## One change to application code, and it was `/develop`'s

`/test` may never touch application code, and this is the one place it would
have had to, so it was made as a build change and is recorded here rather than
hidden. `transcribe.rs` had no seam through which the request could be read:
everything was built inline inside `connect`, which needs a live socket. So the
options builder was extracted as `stream_options`, a pure function, and
`connect` now calls it. **That is what turned record 0005's AC-14 and record
0006's AC-3 and AC-12 from guards into assertions about the real query**, which
is the difference between proving the code says the right thing and proving the
request is the right thing. It changed no behaviour, and
`what_is_asked_of_deepgram_is_decided_in_exactly_one_place` now keeps it the
only options builder in the file.
