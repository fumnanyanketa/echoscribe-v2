## Why this cluster is owed rather than typing

This project has already settled that a label a person reads is not a build
detail. `design/registry.md`'s `Setting label` row says the word "Hotkey" is
"the comp's own... so it is not invented by a build; the user confirmed it on
2026-09-04". Neither of these two surfaces is in the comp at all, so there was
no comp to take a word from and no user in the room to confirm one. Left alone,
whichever line of code was written first would have decided all nine.

The last item on record 0006's list is not wording but a missing state. A filter
can match nothing, `design/design-system.md`'s mandate rule 4 requires an empty
state drawn rather than assumed, and neither the record nor the patrol had drawn
one. That is `/canvas`'s to register, and it was registered before the build.

## What was decided, and where it now lives

All ten went into the records and the registry before any code was written.
Record 0005's fourth section from the end, "The wording of the screen", and
record 0006's equivalent, both carry them, and each is listed in that record's
"Decided on the user's behalf".

| Owed | Answer | Reversible because |
|---|---|---|
| Vocabulary add field's label | "Add a word or phrase" | One string in one file, in Rust's sibling on the screen side, changed without touching a table |
| Its action | "Add" | Same |
| Whether it has a placeholder | No placeholder. It has a real label, and a placeholder that repeats a label is noise that vanishes the moment somebody types | Same |
| The list's label | "Your words" | Same |
| Remove on a row | "Remove" | Same |
| The room left line | "Room for {n} more characters." and, at nothing left, "No room left. Remove a word to make space." | Same |
| The empty state's paragraph | "Nothing added yet. The words to add here are the ones Deepgram keeps getting wrong: names, places, and the jargon of your work. Add one above and your next dictation will listen for it." | Same |
| The language list's label | "Language" | Same |
| The filter's label | "Find a language" | Same |
| The filter's match count | "{n} languages match.", "1 language matches.", "No languages match." | Same |
| What the list shows when nothing matches | The sentence above and no rows. The filter keeps what was typed, so a person can correct it rather than start again. Registered in `design/registry.md`'s `Language filter` | The state stays either way; only its wording is a string |

Nothing in this cluster changes a stored value, a command, a table, an event or
a capability, which is what makes all eleven cheap to reverse: each is a string
on one screen, and a Rust guard in each feature already fails the build if a
sentence Rust owns appears on a screen, so the division cannot rot.

## What the gate did not fire on, and deliberately

Two things looked like candidates and are not owed.

- **The 64 language names.** They have a named source, Deepgram's own table,
  read on 2026-09-04 and reproduced in record 0006. That the source is
  English-only is a real gap and it is recorded as one, in record 0006's Still
  open and in the patrol, but it is a gap in the answer rather than a missing
  source.
- **Every colour, space and radius on both screens.** `design/registry.md` now
  holds a row per component and `design/design-system.md`'s mandate governs the
  rest, so these are AGENTS.md-governed and explicitly not owed.
