THE SIGN IN SCREEN ITSELF IS FINE

Screenshot: AC-7-sign-in-screen-after-restart.png

So the screen is built and reachable. What is broken is only the handover: the
dashboard is destroyed and the small window is never shown.


A HYPOTHESIS, OFFERED AS A HYPOTHESIS

/check does not fix anything and did not test this, so it is a lead for /debug
rather than a conclusion. In src-tauri/src/shell/mod.rs, settle() calls
dashboard_window::close(app), which calls window.destroy(), and then immediately
calls settle_small_window(app). settle_small_window asks
dashboard_window::is_open(app) and hides the small window when the answer is
yes. If destroy() is deferred, as a queued window close, then the dashboard is
still gettable at that instant, is_open() answers yes, and the small window is
hidden instead of shown. The window is then really destroyed a moment later and
nothing runs settle_small_window again.

If that is the cause, it is the shape AGENTS.md standing rule 14 names: the call
returning tells you the destroy was accepted, not that the window has gone.
