## What was built

- `src-tauri/src/diagnostic_log.rs`, new. Opens `echoscribe.log` beside the
  database (the folder comes from the same `app_data_dir()` call the six
  features use), rotates it to `echoscribe.log.1` when it is over 1 MB,
  creates a pipe, points the process's standard error at the pipe, and runs
  one thread that reads the pipe line by line, prefixes each line with the
  UTC time and appends it to the file. On a dev build each line is also
  echoed to the console it would have gone to. A panic hook writes the
  crash line straight into the file before Rust's own hook runs.
- `src-tauri/src/lib.rs`: `diagnostic_log::init(app)` is the first call
  inside setup, before `sign_in::init`, guarded with `if let Err` so a log
  that cannot be opened never stops the app.
- `src-tauri/Cargo.toml`: the `windows` crate gains the
  `Win32_System_Console` feature for `GetStdHandle` and `SetStdHandle`. No
  new library.
- Not converted: the 92 `eprintln!` lines across the feature folders, as
  the record decided. Redirecting the stream makes them land in the file as
  they are.
- `src-tauri/src/dictate/mod.rs` and `src-tauri/src/sign_in/mod.rs`: one
  line each reworded, because the new AC-3 guard refused them. Neither
  formatted a secret; one read `cause.code()` (a stop reason) and the other
  `{code}` (Clerk's error name). Both now format a local called `reason`.
  A false positive is reworded, never exempted, per the record.

Tests: 366 passing, up from 354. `cargo clippy --all-targets -D warnings`
clean. Twelve tests are new, all in `diagnostic_log.rs`.

## The privacy policy sentence, for approval

Proposed as a new paragraph under "What EchoScribe stores on your
computer" in `site/privacy.html`, after the paragraph about Credential
Manager:

> EchoScribe also keeps one small diagnostic file, `echoscribe.log`, in the
> same folder as the database. Each line in it is the time and a plain
> sentence about something that went wrong inside the app, such as the
> microphone not opening or Deepgram not answering, so that if you write to
> us about a problem it can be read rather than guessed at. It never holds
> the text of a dictation, any audio, your Deepgram key, your sign-in
> session or a sign-in code. It is capped at one megabyte with one previous
> copy kept beside it, and it stays on your computer unless you choose to
> send it to us.

The existing sentence "it is never written to any log or file", about the
key, stays true and stays where it is.

## What a person checks, on the installed build

1. Install the next build, launch it, open
   `%APPDATA%\com.echoscribe.app\` in Explorer. `echoscribe.log` is there,
   its first line is today's date and time in UTC followed by
   `log: EchoScribe <version> started`.
2. Switch the microphone off in Windows settings, press the hotkey, read
   the error on the pill, then open the file again. The last lines name the
   microphone failure in plain words, with a time, and nothing you have
   ever dictated appears anywhere in the file.
3. Search the file for your key's last four characters. Nothing is found.
