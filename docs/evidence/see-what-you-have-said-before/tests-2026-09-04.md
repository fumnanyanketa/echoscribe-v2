## What a machine now watches, criterion by criterion

Record 0007 has 13 acceptance criteria. **Seven are covered, two are covered in
half, and four cannot be automated here at all.** The reason is the same one
records 0005 and 0006 hit on the same day and it has not changed: **this project
has no JavaScript test runner**, so no screen in EchoScribe has any automated
coverage of what it draws. What a Rust test can do about a screen is read its
source and fail the build if a promise disappears from it, which is a real guard
and is not the same thing as running the screen.

## The four things a person has to check by hand, every time

These do not become automated later by trying harder. They need a running app, a
real screen and a pair of eyes, and they belong to `/check verify`.

1. **The dashboard lands on History** (AC-1), and the rail shows History above
   Settings with History marked as the one showing.
2. **What a row looks like** (AC-2): the transcript, and beneath it the time in
   this machine's own conventions, the duration, and the language code. A long
   dictation is a tall row and nothing is cut off.
3. **The empty state** (AC-8), which is the first thing every new person sees:
   "Nothing dictated yet.", the keycap for whichever hotkey is chosen, the
   paragraph, and "Change the hotkey" moving the rail to Settings, Dictation.
   **And that no search field is drawn there**, which is what `/develop`'s gate
   settled and is the one part of this screen that changes shape.
4. **A dictation in a right to left script** (AC-11). `dir="auto"` is set and
   guarded, and only a person can see whether the line reads the right way
   round. Record 0006's Still open asks for the same proof for the pill, so one
   sitting with one Arabic or Hebrew dictation answers both.

Two more are half manual and are named above: that a refused search leaves what
was typed in the field (AC-6), and that the read failure state draws no control
at all (AC-10).

## Three invariants broken on purpose

Green is not proof. Each of these was broken in the application code, the suite
was run, the named tests failed, and the code was put back.

1. **The account scope removed from the paged read**, `WHERE account_id = ?1`
   turned into a clause that is always true. Two tests failed:
   `one_accounts_history_is_invisible_to_another` and
   `a_search_never_matches_another_accounts_dictations`. This is AC-9 and record
   0002's AC-18, and it is the failure that would matter most.
2. **The `LIKE` escaping removed** from `like_pattern`. Three tests failed:
   `a_percent_sign_in_a_search_is_searched_for_and_not_used_as_a_wildcard`,
   `a_backslash_in_a_search_is_searched_for`, and
   `an_underscore_in_a_search_is_searched_for_and_not_used_as_a_wildcard`.
3. **The tiebreak dropped from the ordering**, leaving `started_at DESC` alone.
   One test failed: `two_dictations_at_the_same_instant_still_have_one_order`.
   That order has to be total or the cursor can skip a row, and two short
   dictations sharing a second is not hypothetical.

**One test was found to be useless by break 2, and was fixed.** The underscore
test originally searched for `file_name` against `the file_name` and
`the filename`. The second is one character shorter, so it matched the pattern
neither way, and the test passed with the escaping deliberately removed. It now
uses `the fileXname`, which the unescaped wildcard does match, and it fails when
it should. That test would have sat green forever protecting nothing, and only
breaking the code on purpose found it. The reason is written into the test so
the next person does not weaken it back.

## What was not tested, and why

- **`get_history`'s own argument handling** is not directly tested, because a
  `#[tauri::command]` takes an `AppHandle` and there is no running app in a unit
  test. Two behaviours live there and only there: **a query of nothing but
  spaces being treated as no query**, and **a half cursor being read as no
  cursor**. Both are one line each and both are named in record 0007. They are a
  real gap and are named rather than papered over with a test of something else.
  Closing it needs either an integration test with a Tauri app, which this
  project has never set up, or those two lines moving into a pure function,
  which is an application change and `/test` may not make one.
- **Nothing in this suite tests the dictate feature's writes**, which is right:
  record 0002 owns `save_dictation` and already tests it. This feature reads.
- **No test asserts what the screen looks like**, only what its source contains.
  A source guard catches a promise being deleted. It does not catch a promise
  being kept badly.

## The one thing this row leaves the suite

`the_rail_holds_no_section_that_does_not_exist` is gone, deleted by `/develop`
in the same change that gave History a screen, per standing rule 11. It named
`history` as the one section with nothing behind it and there is no such section
left. What replaces it is
`the_rail_holds_history_and_settings_with_its_four_sub_sections`, which asserts
the whole list in order, so an item added without a screen still fails a test.
That is a weaker guard in one way and a stronger one in another: it no longer
names the thing to watch for, and it now catches anything at all appearing in
the rail rather than one named string.
